## 1. Goal

Keep the existing quality gate honest as the project becomes multiplatform, and add iOS coverage without paying for it on every pull request.

## 2. Why this way

The existing CI is well-built: two jobs, zero secrets (fork-safe), JDK 21 pinned, `--max-workers=2` to cap memory on a 7 GB runner, and a hard AAB ceiling written into the workflow. It needs three changes and no redesign.

1. **`detektMain` → `detektAll`** — the silent-coverage-loss fix. Executed as part of `20-01`, listed here so the CI story is in one place.
2. **`AAB_MAX_BYTES` raised to 24 MiB** — once, deliberately, with measured deltas in the comment. Executed in `20-09`.
3. **A nightly iOS job**, not a per-PR one. GitHub bills macOS runners at **10× minutes** and Kotlin/Native linking is slow. A nightly link check catches breakage within a day at a fraction of the cost.

**Do not add iOS to the PR job.** It is the single most expensive mistake available here, and the feedback it buys is not worth ten times the bill for a solo developer.

## 5. Steps

1. **Confirm the `detektAll` swap** landed in `20-01` and CI uses it.

2. **Keep the size job's structure.** It installs the pinned NDK, builds `bundleRelease` with `--no-configuration-cache`, and writes a markdown table to the run summary. That table is the size ledger's source — preserve it.

3. **Add the nightly iOS workflow** on `macos-15`, `schedule` + `workflow_dispatch` only. Never `pull_request`.

4. **Keep CI secret-free.** The current design means fork PRs run the full gate. Signing and Play upload live outside CI, and that is deliberate.

5. **Update the `AAB_MAX_BYTES` comment** with each measured delta as migration tasks land. The comment is the ledger of record.

6. **Push over SSH, not the API.** The `gh` token lacks the `workflow` scope; editing workflow files through the API fails. Edit locally and push.

## 6. Code skeleton

```yaml
# .github/workflows/ios-nightly.yml
# Nightly, not per-PR: GitHub bills macOS runners at 10x minutes and Kotlin/Native
# linking is slow. A daily link check catches breakage within a day for a fraction
# of the cost.
name: iOS nightly

on:
  schedule: [{ cron: '0 3 * * *' }]
  workflow_dispatch:

concurrency:
  group: ios-nightly
  cancel-in-progress: true

jobs:
  link-framework:
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '21' }
      - uses: gradle/actions/setup-gradle@v4
      - name: Link the iOS framework
        run: ./gradlew :composeApp:linkDebugFrameworkIosSimulatorArm64 --stacktrace
      - name: Build the iOS app
        run: |
          xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp \
            -destination 'platform=iOS Simulator,name=iPhone 17' \
            -derivedDataPath build/DerivedData build | xcpretty && exit ${PIPESTATUS[0]}
```

## 8. Pitfalls

- **Do not add iOS to the PR job.** 10× billing, slow links, and the failure it catches is rare enough for a nightly cadence.
- **`--max-workers=2` is deliberate**, not a leftover. The runner has ~7 GB and the Kotlin daemon will OOM without it.
- **`testDebugUnitTest`, not `test`.** The release variant OOMs.
- **`--no-configuration-cache` on the size job** is there for a reason — do not remove it as an optimisation.
- **`xcpretty` swallows exit codes.** `exit ${PIPESTATUS[0]}` is what makes a failed iOS build actually fail the job. Without it the job goes green on a broken build — the same class of bug as piping Gradle through `grep`.
- **The `gh` token lacks `workflow` scope.** Edit workflow files locally and push over SSH.
- **Do not introduce secrets.** Fork-safety is a deliberate property of the current design.
